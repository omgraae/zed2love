# zed2love Skill

Use this skill when developing, configuring, running, or packaging LÖVE2D games in a `zed2love` repository inside the Zed editor.

## Architecture & Editor Setup

1. **Language Server (`lua-language-server` only)**:
   - `.luarc.json` configures `"runtime.version": "LuaJIT"` and loads official LÖVE 11.5 type definitions from `"${3rd}/love2d/library/"`.
   - **Never** add `local love = require(...)` to game files; `love` is a global table provided at runtime by LÖVE2D and declared in `.luarc.json`.
   - `.zed/settings.json` explicitly disables `emmylua` (`"language_servers": ["lua-language-server", "!emmylua"]`) because `emmylua_ls` does not bundle `${3rd}/love2d/library/` and causes false `undefined global variable: love` diagnostics and broken auto-requires.

2. **Virtual Coordinates, `lovemap.draw()`, & Fullscreen (`src/lovemap.lua`)**:
   - `local lovemap = require("src.lovemap")` manages virtual game coordinates, automatic letterbox/pillarbox scaling, mouse coordinate translation, fullscreen hotkeys, and shaders.
   - `lovemap.aspect(w, h, opts)` sets the virtual coordinate space to `(w * 100) x (h * 100)` (e.g. `lovemap.aspect(16, 9)` creates a `1600 x 900` virtual canvas regardless of window pixel resolution) and installs automatic hooks into `love.draw`, `love.handlers.resize`, and `love.handlers.keypressed`.
   - In `main.lua`, define **`function lovemap.draw()`** instead of `function love.draw()`. `lovemap` automatically invokes `lovemap.draw()` inside the virtual coordinate canvas and handles `F11` (toggle fullscreen), `Escape` (exit fullscreen), and window resizing without boilerplate callbacks.
   - Use `lovemap.getMousePosition(clamp)`, `lovemap.toGame(sx, sy, clamp)`, and `lovemap.toScreen(gx, gy)` to convert between window pixels and virtual coordinates.

3. **Full-Screen & Per-Object Shaders (`src/moonshine/` & `src/lovemap.lua`)**:
   - `src/moonshine/` embeds an updated, LÖVE 11.5-compatible version of `vrld/moonshine` (17 effects: `boxblur`, `chromasep`, `colorgradesimple`, `crt`, `desaturate`, `dmg`, `fastgaussianblur`, `filmgrain`, `fog`, `gaussianblur`, `glow`, `godsray`, `pixelate`, `posterize`, `scanlines`, `sketch`, `vignette`).
   - **Full-Screen Shader Chains**: Call `local fx = lovemap.setShaders("crt", "scanlines", "vignette")` and configure parameters via `fx.<effect>.<param> = value` (e.g. `fx.scanlines.opacity = 0.25`).
   - **Per-Object / Per-Group Shaders**: Create an effect chain with `local obj_fx = lovemap.newEffect("chromasep", "glow")` (or a raw `love.Shader`) and wrap specific draw calls inside `lovemap.draw()` using `lovemap.withEffect(obj_fx, { chromasep = { radius = 5, angle = t } }, function() ... end)`. `lovemap.withEffect` clears the effect buffer with transparent alpha (`0, 0, 0, 0`) so it composites over the existing scene without wiping the background.

4. **Included Example Games (`examples/<gamename>`)**:
   - `examples/train_ride`: Side-scrolling steam train with 5 background parallax layers, 2 foreground parallax layers, stationary sky, and depth-based atmospheric haze shader (`lovemap.withEffect`).
   - `examples/mario_clone`: Platformer with 3 playable levels, coins, question blocks, patrolling enemies, moving platforms, and goal flagpoles.
   - `examples/solitaire`: Klondike Solitaire with spring-damper physical card motion, velocity-based card tilt, and a full-screen CRT + scanlines + vignette shader chain.
   - `examples/wolfendoom`: 3D raycaster mapping PNG textures (`assets/wall_brick.png`, `assets/wall_tech.png`, `assets/monster.png`) to virtual wall columns and depth-sorted respawning monster billboards.
   - `examples/utopia`: Peaceful turn-based isometric civilization game on a large map focused on cooperative trade routes, shared resources, and mutual aid during natural emergencies.
   - `examples/shadermaxxing`: Autogenerated top-down isometric maze showcasing a 3D rolling ball shader, 360° raytraced 8-segment vision, fog-of-war mist, directional `motionblur`, impact `screenshake`, `glow`, `chromasep`, `vignette`, and `filmgrain`.

5. **Cross-Platform LÖVE Binary Locations (`.zed/tasks.json`)**:
   - **macOS**: `"/Applications/love.app/Contents/MacOS/love"`
   - **Linux**: `"love"` (or `"/usr/bin/love"`)
   - **Windows**: `"C:\\Program Files\\LOVE\\love.exe"`

## Build & Run Commands (`Makefile` & Zed Tasks)

- **Run Main Game Locally**:
  - Zed Task: `"Run Game"` (bound to `Cmd+Return` in `~/.config/zed/keymap.json`)
  - CLI: `make run`
- **Run Any Example Game**:
  - Zed Tasks: `"Example 1: Train Ride"`, `"Example 2: Mario Clone"`, `"Example 3: Solitaire (CRT)"`, `"Example 4: Wolfendoom 3D"`, `"Example 5: Utopia (Isometric)", "Example 6: Shadermaxxing"`
  - CLI: `/Applications/love.app/Contents/MacOS/love examples/<gamename>`
- **Package `.love` Archive**:
  - Zed Task: `"Package .love"`
  - CLI: `make love` (outputs `build/zed2love.love`, excluding `.git`, `.zed`, `Makefile`, `skills/`, `build/`, etc.)
- **Build for WebAssembly (WASM)**:
  - Zed Task: `"Build WASM"`
  - CLI: `make wasm` (packages `.love` and runs `love.js` in compatibility mode `-c` to generate `build/web/`)
  - Dependencies: `zip`, Node.js (`npm`/`npx`), and `love.js` (`npm install -g love.js`).
- **Serve WASM Locally**:
  - Zed Task: `"Serve WASM"`
  - CLI: `make serve` (builds WASM and serves `build/web/` at `http://localhost:8000` via `python3 -m http.server`).
- **Clean Build Artifacts**:
  - Zed Task: `"Clean Build"`
  - CLI: `make clean`

## WASM Compatibility Guidelines for LÖVE2D (`love.js`)

- Keep total asset size reasonable and adjust `MEMORY` in `Makefile` (default `67108864` / 64 MB) if the game loads large textures or audio files.
- Avoid native LuaJIT FFI C libraries or OS-specific shell calls when targeting `wasm`, as `love.js` runs in a browser WebAssembly sandbox.
